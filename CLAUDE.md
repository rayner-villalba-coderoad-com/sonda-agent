# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Sonda is a pcap/pcapng analyzer with an AI agent: it parses captures in the browser, shows a dashboard, runs heuristic attack detections, proposes and tests Snort rules, and lets the user chat with Claude about the capture. The UI, identifiers, tool names, log messages and docs are in **Spanish**. Keep new code and user-facing strings in Spanish too.

No dependencies, no build step, no bundler, no test suite, no linter. Plain Node.js ≥18 on the server, plain browser JS (IIFEs, no modules) on the client.

## Commands

```bash
npm start                                         # server at http://127.0.0.1:3000 (reads .env)
npm run ejemplo                                   # writes ejemplo.pcap with simulated attacks
npm run analizar -- ejemplo.pcap                  # CLI analysis: summary + findings, no AI
npm run analizar -- captura.pcap --reglas local.rules   # also export the suggested rules
npm run analizar -- captura.pcap --archivos dir         # also write extracted files + SHA256SUMS
npm run analizar -- captura.pcap --pdf x.pdf --iocs x.csv --stix x.json --caso ID --tlp amber   # deliverable report
```

Since there are no tests, the quickest check for changes to `public/engine.js` is `npm run ejemplo && npm run analizar -- ejemplo.pcap`. The sample capture comes from `Engine.sampleCapture()`, so a new detection should come with matching simulated traffic there. Its `frame()` draws `rand()` for every packet, so new traffic should be appended at the end of the generator to keep the earlier packets (and the detections tuned on them) stable. To check extraction: `npm run analizar -- ejemplo.pcap --archivos /tmp/x && (cd /tmp/x && shasum -a 256 -c SHA256SUMS)` should list 7 files, all OK.

Config is in `.env` (copy it from `.env.example`): `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL` (default `claude-sonnet-5-5`), `MAX_TOKENS` (capped at 16000), `PORT`, `HOST` (default `127.0.0.1`; binding wider exposes the API key to anyone on the network), `ANTHROPIC_API_URL`. Without a key, parsing, the dashboard and suggested rules still work. Only the agent and chat are disabled.

## Architecture

**The capture never leaves the browser.** `server.js` only serves `public/` and proxies `/api/messages` to the Anthropic Messages API, adding the key. It forwards just `messages` and `tools`, and the server always sets `model` and `max_tokens`. `/api/health` reports whether a key is configured. Responses are not streamed.

**`public/engine.js`** is the core and runs in three environments: Node, the page, and the Web Worker. It is an IIFE assigned to a global `Engine`, plus `module.exports` for Node (used by `scripts/`). It must stay free of DOM and Node APIs. Its public surface is the object returned at the bottom (`parse`, `summary`, `testRule`, `parseRule`, `sampleCapture`, …). The pipeline:

1. `parse(buf)` sniffs the magic number and calls `readPcap` or `readPcapng`. These yield via `tick()` so the UI can show progress.
2. Each packet goes through `handle` → `decodeLink` → `ipv4`/`ipv6`/`arp` → `l4` → app decoders (`parseDNS`, `parseHTTP`, `parseSNI`), building a packet object `p`.
3. `account(M, p)` updates the model `M` (from `newModel()`): stats, hosts, flows, DNS/HTTP/TLS lists, cleartext creds. It also feeds detection accumulators in `M.acc` (`detAcc`, `dnsAcc`, `httpAcc`). Only the first `MAX_PKTS` (250k) packets are kept in `M.pkts`, but the stats cover every packet.
4. `finalize(M)` builds derived lists (`hostList`, `flows`, `flowById`, `timeline`, …). Then `extractFiles(M)` (async) fills `M.files` and `M.fileNotes`, and `detect(M)` turns the `M.acc` accumulators (and `M.files`) into `M.findings`.

**TCP reassembly and file extraction** also live in `engine.js` and work over `M.pkts`. `flowAcc` tags every packet with its flow id (`p.fid`); TCP packets cut short by the snaplen get `p.seglen` (the real segment length). `tcpConnections(M, fid)` splits a flow into connections when a SYN brings a new ISN, `reassemble(pkts)` returns `{client, server, dirs}` where each direction has a gap-filled `bytes` buffer plus `chunks`, `gaps`, `missing` and `retrans`, and `followTcp(M, fid, k)` adds the interleaved `turns` used by the UI and the agent. Extractors: `httpFiles` (Content-Length, chunked, until close, gzip/deflate via `DecompressionStream`, multipart), `ftpFiles` (matches `PASV`/`EPSV`/`PORT`/`EPRT` to the data flow) and `smbFiles` (SMB2 `CREATE`/`READ`/`WRITE` keyed by FileId). Every file goes through `addFile`, which sanitizes the name (`safeName`; names come from the capture and become file names on disk), computes `sha256` (pure JS on purpose: WebCrypto needs a secure context) and the real type (`fileMagic`). The executable finding is emitted last in `detect()` so the earlier sids do not shift.

To add a detection, first collect the evidence in an accumulator during accounting (add a field to `acc` in `newModel()`), then emit a finding in `detect()` via `add({...})`. A finding looks like `{sev: 'alta'|'media'|'baja', cat, title, t, tEnd, ips, desc, evidence: [...], rules: [...], phase, mitre}`. `phase` is one of the ids in `PHASES` (`reconocimiento`, `acceso`, `c2`, `exfiltracion`, `impacto`) and decides the lane in the incident timeline. `mitre` is built with `att('T1046', ...)`: the first technique is the primary one, and every id must exist in the `ATTACK` table (official English name plus tactic in Spanish). `add()` appends `reference:url,attack.mitre.org/techniques/<primary>/` to each rule, so do not add it yourself. `tEnd` is the last event of the finding (the bar end in the timeline). `incident(M)` groups the findings by phase and also returns the hosts seen in more than one phase and whether the phases follow kill-chain order. Build rules with the local `R(header, {msg, body, cls})` helper: it assigns sequential sids from 1000001, and rule messages are prefixed `SONDA`.

The Snort rule tester (`parseRule` / `compileRule` / `packetMatches` / `testRule`) is a partial reimplementation that runs over `M.pkts`. It supports only the options listed in the README's "Limitaciones" section. Unsupported options are reported in `ignored`, not treated as errors.

**`public/local-runtime.js`** provides `window.claude.use('sample' | 'downloads')`. `app.js` was written against this capability interface, so keep its shape. `sample(input, {tools, signal, onText})` runs the tool-use loop client-side: it calls `/api/messages`, executes the requested `tool_use` blocks in the browser against the loaded capture, appends `tool_result`s, and stops after `MAX_ROUNDS` (12). `sample.json` wraps it to parse JSON. `use('sample')` returns `null` when `/api/health` says there is no key, which `app.js` treats as "AI off".

**`public/app.js`** holds all the UI: tabs, dashboard (hand-built SVG/HTML strings, always escape with `esc()`), packet and flow tables, findings, the rules editor, the Markdown report, and chat. State lives in the single object `S` (`S.M` is the parsed model). The "Incidente" tab (`renderIncident`/`drawIncident`) draws the phases as a Gantt chart. Severity colors are the app's status tokens: `media` and `baja` are too close to tell apart by color alone, so `baja` bars are drawn as an outline only. Keep that if you touch the chart. "Exportar capa ATT&CK Navigator" writes a Navigator layer (format 4.5). To add an agent tool, append `T(name, description, properties, fn)` to `TOOLS`. Also add a progress label to `TOOL_LABEL`. Tool functions call `need()` to get the loaded model and should return compact, truncated objects, since results are capped at 60k chars. Anything a tool returns is sent to the API, so stream text goes through `maskSecrets` first.

Script load order in `index.html` matters: `local-runtime.js` (defines `window.claude`), then `engine.js`, then `report.js`, then `app.js`.

**`public/report.js`** (global `Report`, also `require`d by the CLI; no DOM, no Node APIs) turns a parsed model into deliverables. `Report.build(M, {file, meta, rules, interp})` returns the report data: executive summary sentences and prioritized actions (rule-based, no AI), the risk level, the incident timeline, findings with evidence, IoCs, affected assets, rules, files and the traffic profile. `pdf(D)`, `markdown(D)`, `iocCsv(D)`, `stix(D)` and `rulesFile(D)` render it. The PDF writer is hand-written: standard Type1 fonts (Helvetica, Helvetica-Bold, Courier) with WinAnsiEncoding, width tables for line wrapping, and `clean()` mapping anything outside WinAnsi to an ASCII substitute or `?`. All drawing goes through `writer()` (`p`, `bullets`, `kv`, `table`, `code`, `h1`/`h2` with bookmarks, `link`). To check a PDF change there is no tool in the repo: render it (macOS PDFKit via a small Swift script works) and look at the pages. In the engine, each finding carries `ioc` (`{type: 'ip'|'dominio'|'url'|'sha256'|'user-agent'|'mac'|'puerto', value, role}`; only external IPs, through `ipIoc`), and `attachEvidence` (run in `parse`, so in the worker) adds `frames` (example frame numbers) and `ruleTests` (hits per suggested rule). That is the expensive part of a report, so keep it out of `Report.build`. `parse` also stores `M.fileSize` and `M.fileSha256` (the chain-of-custody hash on the cover).

**Parsing runs in a Web Worker** (`public/worker.js`, which loads `engine.js` with `importScripts`) so large captures do not freeze the UI. `loadBuffer` in `app.js` creates the worker and only transfers the capture after the worker posts `ready`. If the worker cannot start (`new Worker` throws, or it errors before `ready`), the buffer is still on the main thread and `Engine.parse` runs there as before. The worker also runs `testRule` for the rules the user already had. It then sends the model back without packets (`Engine.forTransfer`: drops parser-only fields and transfers the capture buffer and the file buffers), followed by the packets in batches of 20,000 with payloads as offsets. `Engine.addPackets` turns those offsets back into `Uint8Array` views on the main thread, so the deserialization is spread over several tasks. Consequences: anything the UI needs from `M` must survive structured cloning (plain data, Maps, Sets, typed arrays, no functions), and a field the UI starts using must not be one that `forTransfer` deletes. `S.loadSeq` discards results from a load that was replaced, and `S.cancelLoad` terminates the worker ("Cancelar" button).
